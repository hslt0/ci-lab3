## Структура проєкту

- `app.py` — створення Flask-застосунку та точка запуску.
- `routes.py` — веб-маршрути й API (`/api/run`).
- `validation.py` — перевірка вхідного JSON-варіанта.
- `solver.py` — спільна логіка розміщення, перевірка правил, фітнес, GA та SA.
- `experiments.py` — дослідження параметрів GA/SA та порівняння алгоритмів.
- `make_hard_variant.py` — генерація складного варіанта `variant_hard.json`.
- `test_app.py` — модульні тести.
- `variant04.json` — варіант студента; `variant_hard.json` — складніший варіант.
- `templates/index.html` — розмітка сторінки.
- `static/css/styles.css` — стилі.
- `static/js/main.js` — робота з інтерфейсом і API.
- `*.csv` — результати експериментів (`_hard` — для складного варіанта).

## Правила та фітнес-функція

Розстановка вважається правильною, якщо виконано всі п'ять правил: орієнтація
(горизонтально або вертикально), перебування в межах поля, відсутність кораблів
на рифах, відсутність перетинів і відсутність дотику кораблів (зокрема по
діагоналі). Дотик до рифів дозволений.

Фітнес — штрафна функція: `F = −(сума штрафів)`. Кожне порушення правила дає
штраф за вагою правила, кожен нерозміщений корабель — додатковий штраф.
`F = 0` означає правильну розстановку. Це значення є умовою зупинки обох
алгоритмів; додатково алгоритми обмежені кількістю поколінь (GA) або ітерацій
(SA). Чим ближче розстановка до правильної, тим менший штраф, тому фітнес
розрізняє дві неправильні розстановки.

## Кодування та алгоритми

**Хромосома.** Вектор цілих чисел довжиною, що дорівнює кількості кораблів.
Ген — «бажаний» номер початкової позиції корабля в списку всіх можливих
положень (клітинка + орієнтація). Кораблі декодуються від найдовшого до
найкоротшого: для кожного береться бажана позиція, а якщо вона недопустима,
перевіряються наступні кандидати (обмежена кількість спроб). Тому кодування
автоматично гарантує правила 1–3 і, завдяки перевірці зайнятих клітинок,
правила 4–5; корабель, для якого допустимої позиції не знайдено, вважається
нерозміщеним і штрафується у фітнесі.

**Генетичний алгоритм.** Початкова популяція випадкова; відбір рулеткою;
одноточкове схрещування з ймовірністю `crossover`; мутація замінює ген на
випадкове значення з ймовірністю `mutation` для кожного гена; елітизм зберігає
`elitism` найкращих особин; зупинка при `F = 0` або після заданої кількості
поколінь.

**Імітація відпалу.** Стан — така сама хромосома (декодується тим самим
декодером). Енергія `E = −F`, тобто `E = 0` — розв'язок. Сусідній стан
отримується зміною одного гена: невеликим зсувом значення або заміною на
випадкове. Прийняття ходу за Метрополісом: гірший хід приймається з
імовірністю `exp(−ΔE / T)`. Охолодження геометричне: `T_k = T₀ · α^k`.
Зупинка при `E = 0` або після заданої кількості ітерацій. Історія SA містить
поточну та найкращу енергію, температуру й частку прийнятих ходів.

Для порівняння алгоритмів основною метрикою є кількість обчислень фітнес-функції
(`fitness_evaluations`), а не кількість поколінь чи ітерацій: одне покоління GA
містить `M` обчислень, а одна ітерація SA — одне, тому покоління та ітерації
між собою непорівнянні.
